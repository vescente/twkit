# twkit: Tableau workbook toolkit for agents

An agent builds, edits and checks Tableau Desktop workbooks through the `twkit` MCP server. A
person opens and publishes them; publishing is their quality gate, not a missing feature.

## Run

```bash
.venv/bin/twkit-mcp                    # MCP server; clients call tools as mcp__twkit__*
```

Registered in the client's `.mcp.json`. Clients see new tools only after a reconnect (`/mcp`).
Settings and data paths live in `~/.twkit/config.toml` (`[paths]`, `[settings]`, `[database]`);
`show_config` reports what resolved. Nothing configured is valid: data-aware checks say so.

## Check

```bash
.venv/bin/python -m pytest tests/ -q                                  # the whole toolkit
.venv/bin/python -c "import sys;sys.path.insert(0,'mcp');from twkit import selfcheck as s;print(s.format_report(s.selfcheck()))"
.venv/bin/python tools/frame_corpus.py                                # after any frame.py change
```

`selfcheck` verifies the toolkit itself: channels wired into `preflight`, every module described,
no dead code, no duplicated or dangling docs. A workbook is checked with `preflight` (all channels
at once) and viewed with `frame_publish`.

## Laws

1. **Never publish.** No uploads to Tableau Cloud, no access tokens, no server connections that
   publish.
2. **The user's workbooks are read-only.** A user workbook is written only through `owner_install`
   (snapshot + diff guard); every other write to it is refused (`owner.check_write`, `[guard]` in
   config). Builders and outputs for specific workbooks live in
   `~/Documents/My Tableau Repository/Workbooks/_ai/<project>/`, never in this repo.
3. **Rules are calibrated on a corpus** of working workbooks. A rule that flags them is wrong.
4. **"Not checked" is not "fine".** Say what could not run.
5. **Save `.twbx` only.**
6. **No DDL** in any database without the owner's permission; reads are free.
7. **No views per dashboard**: the workbook's SQL goes straight to the marts.
8. **XML only through `twkit/safexml.py`** (`from_twbx` / `to_twbx`); a test enforces it.
9. **Public-ready repo**: tool code, tests, dev tools and docs only. No hosts, logins, company or
   workbook names, personal paths. English only, minimal comments.

## The loop

Every finding leaves three things, or it dies with the session:

| what | where |
|---|---|
| a check | `mcp/twkit/<channel>.py`, wired into `preflight` |
| a test | `tests/`, failing without the fix |
| a line | the ONE document that owns this kind of knowledge (below) |

## Where knowledge lives

One kind of knowledge, one document; others link to it.

| knowledge | document |
|---|---|
| modules, check channels, frame, editing the owner's workbook | `mcp/twkit/README.md` |
| dev scripts | `tools/README.md` |
| test suites and conventions | `tests/README.md` |
| craft: clear, insightful dashboards | `docs/DESIGN_KB.md` |
| corpus measurements (numbers) | `docs/STYLE_GUIDE.md` |
| names of fields and sheets, data pane folders (lint `R35`) | `docs/NAMING_RULES.md` |
| facts from installed Tableau and its docs | `docs/TABLEAU_APP_NOTES.md` |
| describing a finished dashboard | `docs/REPORT_DOC_STANDARD.md` |
| the XML dialect (generated by `tools/xsd_notes.py`) | `docs/FORMAT_NOTES.md` |
| one specific workbook | its consumer folder under `Workbooks/_ai/` |

## Build order

1. `house_style_rules` · `design_rules`: style and composition.
2. `list_tables` → `table_schema` · `metric_canon`: the data and how each metric is computed.
3. `spec_reference` → `validate_spec` → build from `list_blocks`; edits through `edit_*`.
4. `preflight`: every channel, plus what did not run.
5. `frame_publish`: look at every page; fix what the critic reports.
6. Tableau capture only where the frame model is known to be blind.

Do not hand-write XML when a block exists, and do not put design rules in code: they live in
`docs/DESIGN_KB.md`.
